# Hardpull Docs

Planning and reference documents for the Hardpull submission. Committed as part of the submission
per the AI-usage disclosure requirement — these are the spec files, prompts, and planning artifacts
the project was built from.

| File | Contents |
|---|---|
| [`context.md`](./context.md) | Project overview, track decision, repo roles, competitive landscape, risks, compliance |
| [`spec.md`](./spec.md) | Product vision, problem statement, entities, functional/non-functional requirements |
| [`architecture.md`](./architecture.md) | System architecture, component details, data strategy, interaction flows, security model |
| [`plan.md`](./plan.md) | Task-by-task implementation plan with dependencies and acceptance criteria |
| [`sponsor-integration.md`](./sponsor-integration.md) | Partner prize strategy — Hedera, The Graph, Chainlink |
| [`DECISIONS.md`](./DECISIONS.md) | Dated log of go/no-go and architecture decisions (e.g. the T-014 CRE viability gate) |

| [`diagrams/`](./diagrams) | Rendered architecture diagrams (T-091), regenerated by `node scripts/render-diagrams.mjs` |
| [`partners/`](./partners) | Per-partner integration write-ups and feedback (T-092, T-093) |

`deployments.<chainId>.json` appears here once `contracts/script/Deploy.s.sol` has run. The
Sepolia file is committed — it is how T-026 publishes addresses; local Anvil output (31337) is
gitignored. `node scripts/sync-deployments.mjs` fans those addresses into every package's env
file and into the Sepolia subgraph manifest.
